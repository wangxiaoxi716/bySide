# bySide 能力接入指南

适用于本机单用户基座。接口版本是 `/api/v1`，扩展清单的 `protocolVersion` 是 `1.0`。启动服务后，打开 `http://127.0.0.1:4173/api/docs` 查看 HTTP 接口；`GET /api/v1/capabilities` 返回当前扩展权限与事件名称。本文说明如何将饮食、棋类等独立程序接入；它们可以使用自己的数据库和技术栈。

## 分工

基座负责伙伴状态、聊天和记忆、成长计算、视觉和语音入口、投影状态与事件流。扩展进程负责自己的业务逻辑和数据，通过 HTTP 注册清单、接收动作，再用扩展令牌提交成长或伙伴回应。基座和扩展各自运行，不要求把扩展代码放进基座的 NestJS 工程。

## 第一步：实现扩展动作

启动一个监听 `127.0.0.1` 的 HTTP 服务。清单里的 `url` 是该服务的本机地址。每个声明的动作对应：

```text
POST <url>/actions/<action>
Content-Type: application/json
```

基座将调用者提供的 JSON 对象原样转发给扩展，并将扩展返回的 JSON 原样返回给调用者。动作名只允许小写英文字母、数字和连字符，最长 60 字符；基座等待扩展响应最多 5 秒。扩展应处理重复调用、保持响应简短，并自行对业务参数进行校验。

## 第二步：注册清单

本机主控调用 `POST /api/v1/extensions`，例如：

```json
{
  "protocolVersion": "1.0",
  "id": "meal-helper",
  "name": "一起吃饭",
  "url": "http://127.0.0.1:4185",
  "permissions": ["read", "growth", "respond"],
  "actions": ["analyze-meal"],
  "events": ["companion.updated", "message.created"]
}
```

ID 应稳定且唯一，只能包含小写字母、数字和连字符，最长 60 字符。`actions` 是基座允许调用的动作；`events` 是扩展订阅时接收的事件类型。新扩展应显式声明这两个数组。兼容旧注册信息时，未声明数组会按未限制动作或事件处理。

请求成功返回扩展 ID 和 `token`。令牌仅在注册时返回一次，基座只保存摘要；请将它保存在扩展自己的本机私有配置中，后续请求通过 `Authorization: Bearer <token>` 发送，不要写入代码仓库或放进浏览器 URL。目前还没有修改清单、注销扩展或重置令牌的接口；重复注册同一 ID 会失败。

权限含义：

- `read`：读取包含最近 200 条聊天和全部记忆的快照，以及订阅声明的事件。申请此权限意味着扩展可以读取这些个人数据。
- `growth`：提交活动事件，由基座计算成长。
- `respond`：更新伙伴当前显示的回应。

## 第三步：调用与订阅

扩展请求下列接口时必须提供自己的令牌：

```text
GET  /api/v1/extensions/{id}/snapshot
GET  /api/v1/extensions/{id}/stream?after=<lastEventId>
POST /api/v1/extensions/{id}/events
POST /api/v1/extensions/{id}/respond
```

例如，用相同的业务事件 ID 重试：

```json
{"eventId":"meal-2026-11-15-dinner", "kind":"meal.completed"}
```

首次提交返回 `duplicate: false`；同一扩展重复提交相同 `eventId` 返回 `duplicate: true`，不会重复成长。当前每个新活动贡献 1 点成长，成长上限为 100；`kind` 用于记录来源，不由扩展直接指定成长数值。一个 ID 应始终对应同一个活动。

事件流为标准 SSE，包含递增的 `id`、`event` 和 JSON 格式的 `data`。扩展应在**成功处理后**保存最后一个 ID；断线时用 `after` 或 `Last-Event-ID` 续传，并容忍重复处理。事件按清单过滤。SSE 不是严格事务消息队列：极端情况下，状态提交后、事件记录前进程崩溃，可能没有对应事件；恢复时应重新读取快照。

浏览器原生 `EventSource` 无法设置 Bearer 头，因此扩展应使用 `fetch` 流或支持自定义头的 SSE 客户端。项目里的 [TypeScript 客户端](../sdk/client.ts) 提供 `BySideClient` 和 `BySideExtensionClient`，后者的 `snapshot()`、`growth()`、`respond()`、`subscribe()` 自动走带权限的扩展接口。一个完整的独立服务和调用示例：

```sh
npx tsx examples/extension.ts
```

先启动基座。示例会注册一个带时间戳的新扩展、启动 4185 端口、调用动作、订阅状态并发送一次成长事件；会修改当前基座的伙伴状态和成长，建议先在测试数据上运行。每次运行会保留一条新的扩展注册记录。

## HTTP 约定

- 请求和普通响应使用 JSON，日期为 ISO 8601。接口在参数无效时返回 `400`，权限不足返回 `403`，找不到资源返回 `404`；错误响应包含 `statusCode`、`message` 和 `error`。未捕获的服务错误可能为 `500`。
- `POST /chat` 要求调用方提供稳定的 `requestId`；成功后的同一 ID、同一内容重试返回原回复，不会重复新增对话或成长。同一 ID 配不同内容会报错。模型处理中同时发送其他聊天请求目前会被拒绝；取消后保留已写入的用户消息。
- `POST /vision` 接收图片 data URL，`mode: demo` 明确表示没有调用模型；与聊天是两个独立接口。`POST /speech` 返回 `{ "mime": "audio/mpeg", "audio": "<base64>" }`。
- `GET /snapshot`、`GET /events` 等是本机主控接口；投影和原界面使用它们。扩展应使用上述带扩展 ID 的接口。

## 信任边界

本版是单机单用户服务，默认只监听回环地址，并检查请求的 Host 和浏览器 Origin。带扩展令牌的请求会按扩展接口和权限检查；基座主控接口及扩展注册仍允许本机无令牌调用。因此，这些权限适合约束遵守协议的扩展，**不能隔离主动绕过接口的本机恶意进程**。在开放网络访问、允许不可信扩展或多用户使用之前，必须增加主控身份认证、用户授权、扩展隔离和令牌生命周期管理。

## 豆包语音

1. 在[豆包语音控制台](https://console.volcengine.com/speech/new/overview?projectName=default)确认已开通流式语音识别和语音合成，并在 API Key 管理中获取新版 API Key。是否可调用取决于账号资源与计费状态。
2. 在项目目录的 `.env` 中配置 `VOLC_SPEECH_API_KEY`。配置文件可从 `.env.example` 创建；已有 `.env` 时只追加或修改相关项，避免覆盖原配置。不要把密钥发到聊天中。
3. 默认识别资源为 `volc.seedasr.sauc.duration`，语音合成为 `seed-tts-2.0`，音色为 `zh_female_vv_uranus_bigtts`。若控制台开通的是并发版、其他版本或其他音色，分别修改 `VOLC_ASR_RESOURCE_ID`、`VOLC_TTS_RESOURCE_ID` 和 `VOLC_TTS_SPEAKER`，资源和音色需相互匹配。
4. 重新启动服务，检查 `/api/v1/health` 中 `speech.asrConfigured` 和 `speech.ttsConfigured`。这两个值只表示填入了密钥，**不代表供应商鉴权已成功**。再在原界面允许麦克风，实际说一句话，并用界面的 TTS 测试验证朗读。

浏览器采集麦克风后，经本机 WebSocket `/api/v1/speech/asr/stream` 发送 16 kHz、单声道 PCM 给基座；基座使用服务端密钥连接[豆包流式识别](https://docs.volcengine.com/docs/doubao-voice/bidirectional-streaming-automatic-speech-recognition-websocket?lang=zh)，返回 `ready`、`partial`、`final`、`ended` 或 `error` 消息。浏览器发送 `{"type":"finish"}` 等待尾句，发送 `{"type":"cancel"}` 或关闭连接会终止识别。音频不写入基座数据库，但会发送至豆包语音服务。

朗读使用[豆包单向流式语音合成](https://docs.volcengine.com/docs/doubao-voice/http-chunked-sse-unidirectional-streaming-v3?lang=zh)，基座收齐音频后返回。未配置 `VOLC_SPEECH_API_KEY` 时，原界面语音输入回退到浏览器识别；原有 `YATUAN_TTS_KEY` 仍可单独用于合成。合成不可用时界面尝试系统语音。已配置豆包识别但连接或授权失败时会显示错误，避免静默切换供应商。
