# 豆包端到端实时语音

基座实现了与 `BySide-YaTuan/duplex_chat.py` 相同的豆包实时对话协议：浏览器和 Node.js 基座之间使用本机 WebSocket，Node.js 再连接豆包的实时语音模型。模型直接生成语音和文字回复，不会再自动调用一次基座的文本聊天模型。

## 开通和使用

1. 在[豆包语音控制台](https://console.volcengine.com/speech/new/overview?projectName=default)确认账号开通**端到端实时语音**，并获取新版 API Key。实时语音与单独的语音识别、合成可能需要分别开通，具体资源与费用以控制台为准。
2. 若项目根目录还没有 `.env`，可从 `.env.example` 创建：`cp -n .env.example .env`。已有配置文件时请直接编辑，不要覆盖它。
3. 在 `.env` 中设置 `VOLC_REALTIME_API_KEY`。也可以留空，复用 `VOLC_SPEECH_API_KEY`；兼容已有终端环境变量 `VOLC_API_KEY`。密钥只保存在本机服务端，不要提交到仓库或发送到聊天。
4. 默认音色是 `zh_female_vv_jupiter_bigtts`。需要换音色时修改 `VOLC_REALTIME_VOICE`，确保该音色可用于已开通的实时语音模型。
5. 构建并重启基座：`npm run build`、`npm start`。如果旧服务占用 4173，先在启动它的终端结束旧进程，再启动新版。访问 `http://127.0.0.1:4173/`，在聊天卡片点击“开始实时语音”。

默认是半双工：芽团播放时发送静音，降低外放回声。戴耳机时可在开启前勾选“耳机模式（可打断）”，说话开始时会清空待播放音频并请求打断当前回复。点击“结束实时语音”或关闭页面会释放麦克风并请求关闭云端会话。

`GET /api/v1/health` 的 `speech.realtimeConfigured` 仅表示本机发现了密钥，**不代表鉴权成功或服务已开通**。没有密钥或上游连接失败时，界面会显示错误，不会伪装成真实语音回复。需要实际说话和聆听，才能验证账号授权、音色、麦克风及音频设备。

## 状态与数据

- 默认伴侣会话为 `default`。云端确认的用户语音转写和模型完整文字回复分别写入基座消息；不会重复请求 `/api/v1/chat`。伙伴气泡及投影通过现有事件流同步。
- 用户语句包含“记住……”时按现有规则写入记忆。完整回复对应的成长与文字聊天共享每 60 秒最多一次的规则；重复收到同一语句的完成事件不会重复写入。
- 发起实时会话时，基座会把已保存的最近记忆和最近完整对话作为上下文发送给豆包；音频也会发送给豆包，但基座不保存原始音频文件。
- 已收到完整文字结束事件的回复会保存；被打断且尚未完整返回的文字不作为完整消息保存。断线后不会自动重新连接，需用户重新开启；新会话会从基座读取最近对话和记忆。
- 原界面的“开始陪伴”已接入同一豆包实时语音会话，同时开启桌面摄像头观察。聊天卡片的纯语音入口继续可用。麦克风由当前会话独占。

## 一边说话，一边观察桌面

在主页打开“开始陪伴”，允许使用摄像头和麦克风，将摄像头对准桌上的食物或物品。连接成功后可直接问“桌上有什么食物”，页面会展示最近观察及识别到的食物。戴耳机时可勾选“耳机模式（可打断）”。

语音由豆包端到端实时模型处理。摄像头默认每 10 秒发送一张最长边 640 像素的 JPEG 到基座，再由图片模型生成结构化观察。模型地址和密钥使用 `.env` 中的 `YATUAN_AI_ENDPOINT`、`YATUAN_AI_KEY`；图片模型 ID 可用 `YATUAN_VISION_MODEL` 单独配置，留空时沿用 `YATUAN_AI_MODEL`。豆包通过内置 `observe_desktop` 工具获取当前画面，基座按需向设备请求新图片，再把结果返回当前语音会话。图片分析期间，音频传输继续进行。

图片模型配置为 DeepSeek 时，`YATUAN_AI_THINKING=auto`（默认）会在请求中明确关闭思考；可改为 `enabled` 或 `disabled`，非 DeepSeek 兼容服务是否支持该参数以服务商为准。这项配置不控制豆包语音模型。观察明确识别到用户提供过包装资料的食品时，结果可附 `foodReferences`：资料来源是用户提供的包装照片，营养值以每 100 克计，并非每包或实际摄入量；默认情况下品牌、品名或口味不清楚时不会附上具体产品数据。芽团可以给出简短的通用饮食建议，不以画面推断疾病、过敏情况或具体摄入量。

仅在用户明确指定饼干和香肠为演示食品时，可设置 `YATUAN_FOOD_DEMO=biscuit-sausage`。系统依据每种食品自身的颜色将盘中浅色食品按饼干、深色食品按火腿肠处理，并给出简短饮食建议；单独出现时也独立判断，未看到的食物不会自动补出。结构化结果以 `classificationBasis: user-specified-test`、`colorTone` 和 `visualCertain` 保留分类依据。用户提供的包装参考同样附有标记，不代表通过画面确认了品牌；其中饼干对应的参考照片实际标注为“干烙蛋糕（恋奶味）”。以具体包装为准，测试结束后留空该变量并重启即可恢复默认匹配。

AR 投影已经开启摄像头时，陪伴面板会复用同源 AR 窗口的采样画面。面板显示“AR 摄像头 · 共享采样画面”。需要先刷新 AR 窗口以加载摄像头共享模块。共享期间由 AR 窗口持有摄像头，结束陪伴会停止采样并释放麦克风，AR 预览继续由其关闭按钮控制。

“暂停观察”会停止采样并清除后端的图片缓存，语音继续连接。“继续观察”重新连接摄像头。摄像头权限被拒绝或画面断开时，界面保留语音并显示错误，可处理后重试。视觉分析失败时会返回不可用结果，芽团会说明暂时看不到画面。

桌面采样图片仅在当前实时会话内存中使用。结构化观察通过 `vision.observed` 事件同步，聊天、记忆和成长继续使用基座已有的持久化规则。面板中的文字输入由基座文字模型结合桌面观察回答，再通过当前豆包连接合成语音。

### 摄像头设备协议

浏览器和外部设备使用同一本机 WebSocket 接口。启用桌面观察时发送以下启动命令。

```json
{"type":"session.start","desktopVision":true,"fullDuplex":false}
```

收到 `session.ready` 后，可定期发送图片。`frameId` 为每张图片的唯一标识，`image` 是 PNG、JPEG 或 WebP 的 data URL，编码后最多 700000 个字符。

```json
{"type":"vision.frame","frameId":"camera-001","image":"data:image/jpeg;base64,..."}
```

- 收到 `vision.capture` 时立即采集一张新图片，在 `vision.frame` 中带回原 `captureId`。
- `vision.frame.accepted` 表示接收成功，`vision.analyzing` 表示开始分析，`vision.observation` 返回 `description`、`foodPresent`、`foods` 和 `observedAt`。时间使用基座收到图片的时间。
- `vision.pause` 和 `vision.resume` 分别暂停、恢复图片接收。设备在暂停后应自行关闭其采集资源。
- 后台采样分析最短间隔为 5 秒，同一会话一次进行一个图片分析。工具调用可按问题发起分析，缺少新图片时等待最多 2.5 秒，仅允许使用 15 秒内的缓存画面。
- `vision.error` 表示本次观察失败，音频连接继续工作。
- `input.text` 携带 `text` 可发送文字问题，`input.error` 表示本次文字输入失败。

TypeScript 中的 `RealtimeCommand`、`RealtimeEvent` 和 `DesktopObservation` 已包含这些消息类型。外部设备只需实现音频帧、摄像头图片和这些命令，设备系统可自行选择。

## 本机 WebSocket 协议

```text
ws://127.0.0.1:4173/api/v1/speech/realtime
```

该接口绑定同一伙伴会话，默认只允许一个实时语音连接。它受现有本机 Host 和浏览器 Origin 检查约束。连接后客户端先发送：

```json
{"type":"session.start","fullDuplex":false}
```

收到 `session.ready` 后发送二进制音频帧：**16 kHz、单声道、PCM s16le，每帧 20 ms、640 字节，并按实际语音速度发送**。服务端返回的二进制帧是 **24 kHz、单声道、PCM s16le**，应流式排队播放。文本帧均为 JSON 事件：

- `session.ready`、`session.closed`：会话启动和结束。
- `transcript.started`、`transcript.partial`、`transcript.final`、`transcript.error`：用户语音识别状态。
- `assistant.text.delta`、`assistant.text.done`：模型回复文字片段及完整结果。
- `audio.started`、`audio.done`、`audio.flush`：音频开始、生成结束、清空待播放音频。`audio.done` 不保证本地扬声器已经播完。
- `response.done`、`response.canceled` 和 `error`：回复或错误状态。

客户端可以发送 `input.commit` 强制判停、`response.cancel` 请求打断、`input.mute` / `input.unmute` 控制上游静音，或者发送 `session.close` 结束。退出时先停止采集，再等待 `session.closed`；断网时基座也会尝试向上游发送关闭事件。

TypeScript 客户端的 `BySideClient.realtimeSpeech()` 可以创建连接并发送启动命令；音频采集和播放由设备端实现。浏览器示例见 [realtime-voice.js](../original-ui/realtime-voice.js)。无需浏览器的设备进程、macOS 适配器及跨平台音频设备协议见 [音频设备接入](音频设备接入.md)。

## 接入工具

可信主控客户端可在 `session.start` 中提供最多 12 个 `tools`，每个工具包含 `type: "function"`、`name`、`description`、JSON Schema `parameters`。收到 `tool.call` 后，客户端按自己的权限执行能力，再回传：

```json
{"type":"tool.result","callId":"模型返回的 callId","output":{"ok":true}}
```

基座将结果与对应 `callId` 返回模型；同一个调用只接受一次结果。这里提供的是标准工具事件通道，**不会自动把所有已注册扩展暴露给模型**：接入方仍需选择工具、校验参数、按扩展权限调用和处理失败。

实时语音是本机单用户原型；主控接口仍信任本机程序。开放网络或允许不可信扩展前，需增加主控身份认证、扩展隔离与设备权限管理。

协议参考：[豆包实时语音全双工接口](https://docs.volcengine.com/docs/doubao-voice/end-to-end-real-time-voice-full-duplex-version?lang=zh)。
