# 独立音频与设备接入

实时语音可以由独立设备进程采集和播放，不依赖浏览器。设备进程使用基座现有的 `/api/v1/speech/realtime` 接口；基座仍负责连接豆包、保存对话和记忆、计算成长、向界面和投影推送状态。不同设备实现同一音频适配器协议即可，豆包密钥留在基座。

```text
麦克风 / 扬声器 ⇄ 设备适配器 ⇄ TypeScript 设备进程 ⇄ 本机基座 ⇄ 豆包实时语音
                                                   └── 对话 / 成长 / 界面 / 投影
```

## 在 macOS 上使用

先启动基座 `npm start`，再打开另一个终端，在项目目录运行：

```sh
npm run voice:native
```

首次运行会编译附带的 macOS 音频适配器，可能需要安装 Apple 开发者命令行工具并允许麦克风权限。适配器使用系统默认声音输入和输出，可在 macOS“系统设置 → 声音”中选择。终端显示“实时语音已连接”后可以说话；关闭浏览器不会停止语音，保持基座和此终端进程运行即可。按 `Ctrl+C` 停止设备和云端会话。关闭该终端、停止基座或断网也会结束语音。

默认半双工：芽团说话及扬声器实际播完后的短暂时间内，发送静音以降低回声。戴耳机时可以用 `npm run voice:native -- --full-duplex` 开启打断；本机适配器目前没有浏览器的回声消除和降噪，外放全双工可能产生反馈。加 `--show-transcript` 可在终端显示文字，默认不输出对话文字。`BYSIDE_PORT` 可修改本机基座端口。

它和页面实时语音共享一个实时会话名额：已在页面开始实时语音时请先结束，再启动设备进程；反之亦然。它不会自动启动或关闭现有页面。其他摄像头或麦克风功能仍可能受实际硬件的设备占用影响。关闭页面后视觉观察和投影画面不会在设备进程中运行；再次打开界面会读取基座保存的对话和伙伴状态。

设备进程运行时，临时识别字幕和说话动作经基座同步到打开的控制页与投影页；说话动画跟随设备播放完成事件。重新打开页面可以恢复当前临时状态，设备结束或断开后自动清除。临时状态不写入消息或事件历史；识别完成的用户消息和完整模型回复仍按基座规则持久化。

## 接入其他设备

为设备提供一个可执行适配器；它可以用 Python、Rust、C++、Node.js 或设备厂商 SDK 编写。适配器可分别选择不同的麦克风和扬声器，管理直接连接的 USB、蓝牙音频设备，也可以作为本机网关连接其他硬件。通过以下方式启动：

```sh
npm run voice:native -- --audio-adapter /绝对路径/your-audio-adapter
```

命令不通过 shell 执行适配器。设备选择、网络连接及硬件专属参数由适配器处理；基座不要求设备是 macOS。项目提供不采集、不播放的[协议模拟器](../examples/audio-device-simulator.cjs)以及 [TypeScript 类型](../sdk/audio-device.ts)。模拟器仅用于检查接线和对接流程，不能代替真实硬件。运行前在类 Unix 系统上赋予适配器执行权限，例如 `chmod +x /绝对路径/your-audio-adapter`。

## 音频适配器协议 1.0

适配器和设备进程通过标准输入、标准输出交换 UTF-8 JSON：**每行一个 JSON 对象**。适配器的标准输出只能用于协议，不要把日志写入标准输出。下面的 `audio` 均为原始 PCM 字节的 Base64，而非 WAV 文件。

启动后，适配器打开设备并在标准输出发送：

```json
{"type":"ready","protocolVersion":"1.0","input":{"encoding":"pcm_s16le","rate":16000,"channels":1},"output":{"encoding":"pcm_s16le","rate":24000,"channels":1}}
```

当前版本要求输入 16 kHz、单声道、16 位小端 PCM；输出 24 kHz、单声道、16 位小端 PCM。采集帧由适配器发送，设备进程会按 20 ms、640 字节重组并按实时速度发给基座：

```json
{"type":"capture","audio":"<输入 PCM 的 Base64>"}
```

设备进程向标准输入发送播放、清空及停止命令：

```json
{"type":"play","id":1,"audio":"<输出 PCM 的 Base64>"}
{"type":"flush"}
{"type":"stop"}
```

适配器必须按顺序播放 `play` 音频，并在每段**实际播放完毕**后回传 `{"type":"played","id":1}`。收到 `flush` 时立即停止并清空待播放音频；收到 `stop` 时释放麦克风与扬声器并退出。设备故障或权限拒绝时发送 `{"type":"error","message":"可读错误信息"}`。适配器异常退出也会使会话结束。开始采集前应获得操作系统或硬件所需授权。

设备进程是受信任的**本地主控客户端**，使用本机实时语音 WebSocket；它不是使用 `read`、`growth`、`respond` 令牌注册的业务扩展。当前基座仅监听本机，不能直接供远端设备安全连接；跨网络设备应由本机适配器充当网关，网关与设备之间的认证和加密需由该适配器实现。不要将当前本机主控接口直接暴露到公网。
