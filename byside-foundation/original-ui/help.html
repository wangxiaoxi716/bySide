01

先准备这三样

HARDWARE

电脑与外接设备

电脑、HDMI 或 USB-C 投影连接线、投影仪、USB 摄像头。麦克风可用电脑自带或外接设备；声音从电脑或指定扬声器播放。

AI SERVICE

视觉与语音服务

图片模型接收兼容 Chat Completions 格式的摄像头图片，豆包端到端实时语音负责听和说。两组服务密钥由本机基座保管。

BROWSER

一个桌面浏览器

需要摄像头、麦克风权限及 Web Audio、AudioWorklet、WebSocket 支持。可以使用桌面 Chrome 打开本机页面。

浏览器采集麦克风并播放音频，后端连接豆包。桌面图片在后端分析后，通过 observe_desktop 工具提供给同一个实时语音会话。
需要确认你需要填写什么放在哪里
接口地址YATUAN_AI_ENDPOINT，兼容图片输入的 Chat Completions 地址电脑项目的 .env
模型名称YATUAN_AI_MODEL，需已开通图片输入能力电脑项目的 .env
实时语音VOLC_REALTIME_API_KEY，豆包端到端实时语音密钥电脑项目的 .env
API Key已开通权限和额度的密钥只填本机 .env，不要发到聊天或网页设置中

服务配置与设备协议见项目内 docs/实时语音接入.md。更换图片模型时，需验证实际图片请求及 JSON 观察结果。

投影仪负责显示；摄像头、麦克风、AI 请求和语音播放，都由电脑上的浏览器发起。

1

把投影设为“扩展显示器”

投影仪连电脑，USB 摄像头也插电脑。系统显示设置选择“扩展”，电脑屏幕留作控制台，投影屏只显示黑底芽团。音频输出选电脑扬声器或你实际连接的音箱。

将摄像头固定在餐桌上方或斜上方，确认盘子在镜头内。拍的是物理餐盘，不是投影画面或网页截图。 尽量把芽团投在盘子旁边，避开摄像头主要观察区。

2

在本机填写 AI 配置

在项目根目录编辑 .env，保留已有的有效配置。当前项目使用以下模型地址，密钥由你在本机填写。

YATUAN_AI_ENDPOINT=https://api.openai-next.com/v1/chat/completions
YATUAN_AI_MODEL=deepseek-v4.1-flash
YATUAN_AI_KEY=在本机填写图片模型密钥
VOLC_REALTIME_API_KEY=在本机填写豆包实时语音密钥

密钥由本地代理服务保管。修改 .env 后，需停止并重新启动服务。不要把这个文件拖入聊天、上传到站点或提交到 Git。

3

启动本地基座

在本项目根目录执行构建和启动命令。

npm run build
npm start

浏览器打开 http://127.0.0.1:4173。保持终端运行；停止服务会让后续 AI 请求无法完成。.env 不放在网页素材目录内。

4

确认接口可用，再打开投影

发送一句普通聊天，确认文字模型能回应。随后开始桌边陪伴，分别确认语音连接和桌面观察。模型地址和密钥统一在服务端配置。

从控制台打开投影，将窗口拖到投影屏，再进入全屏。AR 已连接摄像头时，陪伴面板会共享其画面。两个窗口使用同一个浏览器、同一个地址来源，例如 http://127.0.0.1:4173。

localhost 和 127.0.0.1 不是同一个网页来源。不要一个窗口用前者、另一个用后者，也不要把本地控制台与已发布云端投影混用。
5

打开“桌边实时陪伴”

打开“开始陪伴”，按浏览器提示允许麦克风与摄像头。首次连接使用系统默认摄像头，可结束陪伴后选择其他设备再开始。AR 已开启时，面板显示共享的最近采样画面。

在控制台或投影页选择一个窗口发起语音，其他窗口通过基座同步气泡与状态。麦克风由当前会话独占。

6

直接和芽团说话

连接后直接问“芽团，看看我今天吃了什么”。芽团会按问题请求当前桌面画面，结合视觉结果回答。也可以说“暂停观察”“继续观察”“结束陪伴”。

浏览器模式需要保持采集页面运行。外部音频设备可按 docs/音频设备接入.md 接入基座。

03

之后，就用声音找它

连接后即可交流

“芽团，桌上有什么？”

可以聊心情、说偏好，或问盘子里的食物。识别到的文字和芽团的回答会显示出来。

没有听到回答时

检查麦克风输入、扬声器输出及面板错误。豆包会话需要有效密钥与服务授权，可结束陪伴后重试。

01听你说话麦克风音频经基座发送至豆包
02理解你的话识别成文字，结合记忆
03看看餐盘需要时附上一张摄像头画面
04AI 给出回应更新气泡、情绪与状态
05开口回答朗读结束后继续听你说

默认在芽团播放时发送静音，减少外放回声。戴耳机时可开启“耳机模式（可打断）”，说话会打断当前回答。

04

观察餐盘，回应有变化的日常

本机摄像头提供实时预览，AI 接收定时采样的图片。共享 AR 摄像头时，面板显示最近一次采样。

INTERVAL

间隔 5 / 10 / 15 秒再看

默认 10 秒。图片分析与语音并行，主动问当前画面时会按需请求新图片。可结束陪伴后调整间隔。

ONE AT A TIME

图片请求按顺序处理

上一轮没结束时不堆积图片。观察开启期间，即使画面相同也仍会定时发送快照；较短间隔会增加请求量和服务费用。

CONTEXT

带着观察结果交流

后台观察更新桌面上下文及页面说明，语音回答按对话进行。画面不可用时，芽团会说明需要检查摄像头。

你执行的操作之后会发生什么
开始陪伴连接豆包实时语音并开始桌面采样。
暂停观察停止采样并清除图片缓存，语音继续。共享的 AR 摄像头由 AR 窗口控制。
继续观察重新开启摄像头，恢复观察流程；权限变化时可能再次提示。
结束陪伴停止摄像头、麦克风听写、语音播放与当前会话请求。
食物照片可以辅助描述看得见的食材和搭配，但不能可靠确定油盐量、过敏原、精确热量或诊断健康问题。芽团会保留不确定性；你可以直接告诉它“这不是鸡肉，是豆腐”来纠正。

采样图片发送至已配置的视觉模型，音频发送至豆包。图片在当前会话内存中使用。聊天、记忆和成长由基座持久化，聊天成长遵循每分钟最多一次的规则。

图片分析失败会显示观察错误，语音继续工作。摄像头断开时会暂停观察，处理后点击“继续观察”。实时语音断开会释放本轮采集资源，可检查配置与网络后重新开始。
05

第一次演示前，做一轮现场验收

先结束 36 秒示例演示，再检查真实链路。用你自己的餐盘，按下面顺序操作。

  • 连通：AI 连接检查通过；发送“你好，芽团”，收到该服务的真实回复。
  • 看得见：预览里能看到 USB 摄像头拍到的真实餐盘；让芽团描述食物，再核对是否准确。
  • 听得见：连接成功后说一句话，屏幕显示正确的转写文字。
  • 说得出：芽团有声音回复；播放自己的声音时没有再次触发一轮自问自答。
  • 能回应变化：移动或更换一道可见食物，等待下一轮有效采样；观察是否给出新的、有依据的反馈。
  • 能同步：电脑控制台和黑底投影同时更新气泡与角色状态；成长变化来自实际保存的互动结果。
  • 能停下：点“暂停观察”后摄像头停止；点“结束陪伴”后没有继续拍照、听写和后台请求。

连接检查成功只代表当前检查的请求可达，不等于所有硬件与视觉能力都已验证。食物识别、声音和投影需分别按上面的步骤实测。

06

你之后给的 GIF，可以直接换成动作素材

你可以用 Seedance 制作，再提供导出的文件。播放这些素材不需要接 Seedance API；动作由芽团当下的交互状态切换。

素材名称对应状态动作建议
idle待机轻轻呼吸、眨眼、小幅摇叶子，适合循环
listening倾听抬头、侧耳、叶子微微竖起
thinking等待 AI 回复歪头、托腮、看向餐盘
speaking语音回答自然摆手、轻微嘴部动作；此版不承诺逐字口型同步
happy开心反馈轻跳、挥手、花朵摆动
eating用餐互动捧碗、点头、邀请一起慢慢吃
sleeping休息闭眼、蜷缩、缓慢呼吸

保持同一套构图

每个动作用相同画布尺寸、朝向、角色比例和脚下落点，四周留出花朵和手脚活动空间。尽量做 2–5 秒可循环动作，画面里不要烧入字幕、对话气泡和状态条。

透明背景更方便

GIF 可以用，但它的透明边缘和色彩有限。若制作工具支持，透明 WebM 或 PNG 序列更适合柔软的毛绒轮廓。黑底素材适合投影，放在小屋里会显示黑色矩形。

交付时注明角色名、动作名、是否循环、背景是否透明。成长若已经画进素材，可按“萌芽 / 花苞 / 单花 / 多花”各交一套；若希望网页继续叠加花朵，给头顶留出一致位置。当前占位动作在收到素材前继续保留，不会把静态文件称作已生成的新动作。

项目已留有素材映射入口：文件放在 dist/assets/motions/，在 dist/animations.js 中按角色与动作关联。你直接提供素材文件即可，后续可由我替换；尚未配置的动作继续显示原形象。

07

现场常见问题

原来那个在线网址，能不能直接用？

在线页面是静态站点。要从它调用真实 AI，需要你可用的 HTTPS 代理服务；本机 .env 只供本地 Node 服务使用，不会自动连到线上网页。这次电脑接投影的场景，直接让控制台和投影都运行在本机地址即可。

手机能不能同时控制电脑投影？

当前实时同步适用于同一电脑、同一浏览器、同一来源的多个窗口。手机和电脑是两台设备，尚未接跨设备同步服务；手机版界面仍可使用，但不能因此认定手机已经与电脑投影实时互联。

摄像头列表里没有外接设备，或者拍到的是电脑前置？

先接好 USB 摄像头，检查系统和浏览器摄像头权限，关掉正在独占摄像头的会议应用，再重新进入选择。第一次授权前，设备名称可能不可见。以预览中的实际画面为准。

麦克风有权限，但说话没反应？

检查系统默认输入设备和麦克风电平，确认豆包实时语音连接成功。面板会显示网络、授权或设备错误。处理后结束陪伴并重试。

能聊天，但图片请求失败？

检查模型是否真的支持图片输入，接口是否接受 Chat Completions 的 image_url 内容项，账户是否有对应模型权限。接口地址、密钥错误、余额不足和网络超时需要分别根据错误提示处理。

投影没同步，或者同一句话被说了两遍？

确认两个窗口地址都以 http://127.0.0.1:4173 开头，且属于同一个浏览器的普通窗口。结束多余页面的陪伴会话，只保留投影页采集与朗读。浏览器隐私窗口不与普通窗口共享同一份状态。

芽团看错了食物，或者没有新观察？

检查取景、光线、遮挡以及面板中的最近观察时间，可以问“再帮我看看”请求新画面，也可以口头纠正食材。观察已暂停时，点击“继续观察”。
